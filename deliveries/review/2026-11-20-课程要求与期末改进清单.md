## 最值得先做的四项修改

### 1. 回答老师要的通用 Agent 对照

建议先做三道，题量是组内安排。保留 A「同源文本检索」与 B「同源检索＋图扩展」的原实验，另设 C「能自行搜索 GitHub、读取讨论、Git 历史与源码的通用 Agent」。A/B 问的是图扩展有何贡献；B/C 问的是用户直接打开一个 Agent，能否以相近代价得到同样可靠的结果。

| 题型 | 怎么出题 | 检查什么 |
|---|---|---|
| 简单事实 | 查一个正式版的发布日期和出处。 | 双方能否直接给对。保留通用 Agent 擅长的题，判断预建图是否划算。 |
| 跨来源追问 | 从一条真实 Issue 出发，问为什么改、最终合并了什么、改在何处。只给共同的题干和起点。 | 按讨论理由、合并提交、实际改动位置逐项判分，点开两边引用。 |
| 边界或反例 | 给定采集截止日，问已有证据能否确认某个改动进入指定版本，并要求交代理由。 | 区分「未收录」「最近可达」「首次发布」；记录答错、证据不足和主动限定结论。 |

给双方同一仓库、截至日期或版本、问题和作答时限。让 C 可以自行检索公开资料，保留完整提示、原答和出处；记录实际可访问范围，单列超出冻结范围的资料。能匹配底层模型就匹配，否则将结果解释为产品端到端比较。事先列必答事实，遮去系统名核对事实、引文支持和过度断言，同时记耗时与可取得的调用成本。预建图成本单列，才能讨论一次查询与反复追问的取舍。公开演示过的题可做展示，若要主张新版本效果改善，再用预先封存的新题验证。老师所要求的最小成果是一组能核查的同题原答。

### 2. 把期末改为能接新问题的现场演示

五分钟讲稿要求现场打开冻结回放。代码中设置 `HISTORYKG_REPLAY_FILE` 会展示已存回答并直接返回，没有在线提问框。正常页面已支持预载真实作业和现场提问。课前把可查询作业、数据库和问答配置装好，用正常模式打开，在教室设备上由另一位同学临时出题。屏幕顺序建议为用户问题 → 有限结论 → 图上走过的关系 → 冻结原文及原始链接 → 改问一句后的新答案。离线回放留作故障备份，标出原运行日期。[五分钟讲稿](../../demo/五分钟讲稿.md) · [原型入口](../../app/main.py) · [已有作业的打开方法](../../docs/p5/README.md)
