# 代码与演化方法素材（阶段草稿）

P3 将选中讨论中的代码定位转换为可复算的有限历史事实。模块接收 P1 依据公开 GitHub URL
自动发现并冻结的仓库、PR 元数据与 profile，不由成员指定案例、提交或文件。
对明确已合并 PR，程序读取官方合并提交和第一父提交，依据 git diff 自动发现 Python 变化；
普通修改、显式改名、复制、增加和删除分别处理。同一路径的两个 SHA 被建模为两个 File，
删除关系指向父提交中实际存在的文件，而非构造一个已不存在的提交后文件。

有限采样以生产代码优先，并在提交之间轮转，避免单一大 PR 占满文件预算。
同时在总计最多 24 个文件状态中预留最多 8 个，按通用规则读取默认快照最浅包入口及
其一层内部 import 目标。这个采样用于给模块职责和依赖回答提供源码依据，规则不读取测试题。
代码模块不从 AST 推断业务动机。讨论中的决定、取舍与理由仍交 P4 的模型抽取，
P3 只提供提交、文件、版本和静态依赖的事实及缺口。

Python AST 分析提取静态 import 与顶层函数/类名称。只有目标文件已经在相同 SHA 的
采样集合中取得时，才输出 Imports 边；外部目标、未采目标、语法失败和读取失败分别记载。
AST 列号使用 UTF-8 字节偏移，模块转换为 Unicode 码点后与冻结文本逐字校验，避免中文、
emoji 等字符造成证据错位。静态 import 不表示运行时加载、调用图或目标代码已执行。

发布最多检查三个正式 Release；没有正式 Release 时记录 tags 接口顺序并有限回退。
Release 身份由规范仓库与原样 tag 共同构成，同提交不同 tag 不合并。
发布说明提及 PR 只产生 MentionsPR；提交可达某 tag 由实际 git 祖先判断支持。
裸 git 缓存每次 fetch 深度最多 64，浅边界造成的否定结果记 unknown，不据此声称首次版本。
所有来源使用公共 SourceDocument，证据保留来源哈希及 Unicode 区间；git 命令和实际输出
随 manifest 保存，调用方可以重算相同范围的关系。

完成的开发验证是本地真实 git 对象的七项测试，并实际通过公共来源合并、主体生成和
图记录校验。默认真实 Flask URL job随后自动完成代码阶段：4 个选中合并提交形成 24 个
文件×SHA 快照，读取 3 个正式 Release，输出 25 条已采内部 Imports、8 条 Touches、
8 条 ChangesTo 和 3 条 HasRelease；24 个 Python 文件均解析成功。

冻结数据复核确认 94 个 P3 来源哈希、104 条证据区间、24 个文件定位、所有关系端点和
六个 manifest 分片哈希一致。有限架构题对 `FlaskClient.session_transaction` 的 6 条
claims 均可定位到同一冻结源码 SHA。这个结果说明证据链可追溯，不替代独立语义评审。
深度 64 的浅 git 历史使 12 个 PR/tag 可达性保持 unknown，181 个未采内部 import 目标
和外部模块保留为 gaps；静态分析不表示目标代码已运行或调用图完整。

P4 的前期调研、架构设计、规划框架、独立试跑与基础 collector 保留原贡献归属。
本角色新增贡献为代码/版本自动模块、静态规则、可消费关系/证据、测试与接口交接。
