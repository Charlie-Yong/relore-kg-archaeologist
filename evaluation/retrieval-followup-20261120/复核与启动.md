# 复核与启动

从仓库根目录打开本机演示。项目配置在原有课程环境的 `.local/full-history-itsdangerous/project.json`。其 `answer` 段实际使用百炼 DeepSeek-V4.1-Flash-1017、启用思考、`reasoning_effort=max`、`max_output_tokens=32768`、`timeout_seconds=240`。每次 HTTP 请求最多等四分钟，内部重试会增加整题等待时间。桌面端本机中转使用已有登录配置，问答不需要另填 DeepSeek Key。建图和抽取单独读取 `model` 配置。

## 课堂操作

1. 打开[本机演示](http://127.0.0.1:8517)，在「想了解这个项目的哪段历史？」里直接输入问题，例如「PR #372 的修改首次随哪个正式版发布？」。
2. 展开答案对应的原文证据。日期可以点到正式发布页，实际修改可以点到合并提交，版本归属可以点到合并与该标签的比较页。冻结记录和程序计算的标签核对说明分别显示。
3. 请现场提问的人换一个号码或版本。能从同一入口继续查。开发机已通过真实表单提交并检查打开的原文链接。[表单运行记录](demo-receipt.json)

本机服务重新启动时，用原有 Neo4j 运行目录和项目环境。数据库已启动时只需第二条。

```sh
runtime=$(cat .local/full-history-itsdangerous/neo4j/runtime-path)
JAVA_HOME="$runtime/java" NEO4J_CONF="$runtime/conf" "$runtime/neo4j/bin/neo4j" console
```

```sh
.venv/bin/python -m streamlit run evaluation/retrieval-followup-20261120/demo.py --server.address 127.0.0.1 --server.port 8517
```

## 实验记录

- 先封存六题、标准出处和三道共同题，再开发。第一次封存的原题号、截止时间和资料散列在 [protocol.json](protocol.json)。开发回归的三个老题来自[上次实验](../agent-comparison-20261120/实验报告.md)。
- 改动前的本地程序快照为 `.local/retrieval-followup/baseline/source.tgz`，包含当时尚未提交的项目改动。基线查询文件相对于提交 `642e68e` 的差异也保存在 [baseline-query.patch](baseline-query.patch)。O 使用该快照，A 使用不沿图关系查找的新版，B 使用新版图谱。C 在 B 的相同原文之外提供至多十条相关关系。D 和 E 分别在本地冻结文件和 GitHub 上自由查找。
- 无前缀记录是最初按 8,192 个输出 token 运行的单元格。以 `dev-` 开头的是原三题回归，`output-` 是 16,384 个输出 token 的同资料复核，`passages-` 是保持 8,192 上限、给原文编号的版本题复核。以 `live-` 开头的是使用 32,768 上限、通过当前百炼入口作答的复测。两道额外题在改编号引用前封存，对应 7、8 号。[补充题与标准事实](citation-check-protocol.json)
- 评分使用独立模型调用，屏蔽组名和耗时，随后核对原文。单个配置每题仅取第一次完整调用（包含预先允许的内部重试）。用量来自回执。人民币实际收费没有独立账单。可在[课堂对照表](课堂对照表.md)点击具体单元格看原答。
- 保留原始首答。实验入口发现已有记录会跳过。新一轮如需独立计时，应复制实验目录并给新记录使用独立输出目录和账本。
