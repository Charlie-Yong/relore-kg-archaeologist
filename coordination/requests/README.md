# 跨模块请求

在本目录新建REQ-YYYYMMDD-角色-序号.md，说明具体问题，不以私聊替代接口记录。

~~~text
请求ID：
提出角色/接收角色：
契约与数据版本：
涉及构建时的repo/job_id/profile/阶段（无则不适用）：
受影响生产者/消费者：
实际输入、实际结果、预期契约：
最小可复现材料位置（不含密钥/私有测试参考）：
所需动作及负责人：
可独立继续的工作/临时方案：
下一次跟进日期：
状态与处理结果：
~~~

提出请求的AI当轮读取上游状态、登记本文件并提交，后续活跃轮同步跟进。P1的AI主动检查requests、交接和PR，组织责任AI修复或补位；公共字段由P1的AI维护、P2的AI复核，评测涉及P6的AI复核。超过一个工作日仍未解决由P1的AI记录影响和补位安排，常规协调无需成员传话。

缺上游时继续同契约fixture、独立代码/测试/文稿，待来源可用补真实联调；等待不等于通过。没有写入/推送能力时如实标“请求尚未落盘/未送达”，并一次请求必要通道；确需本人动作才按人工接管格式提出。仓库同步发生在AI活跃时，本说明不唤醒离线会话。

P1的AI明确移交，或待审PR/请求超过一个工作日无P1处理记录时，P2的AI在自身活跃轮按契约C3.3代行已有权限内的集成核验。接手记录写已有STATUS/handoff，P2本人PR仍需独立AI复核；缺权限先留可审PR与恢复点，不增加人工值班、填表或催交。
