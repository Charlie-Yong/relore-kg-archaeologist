# relore 项目历史知识图谱｜六人 AI 执行规划

基于 relore 的开源项目历史可追溯知识图谱构建与应用，以 Flask 为首选试点。

**当前交付：规划 v1.0 / 契约 1.0.0。** 仓库内是总方案、接口约定、六人工作单和状态模板；系统实现、真实数据、模型调用、图库和正式实验均待后续执行。

## 成员如何开工

组长将成员对应到 P1–P6，每人把自己的一份完整文件交给 AI。文件已内嵌共同规范，不需要再读旧规划或复制聊天内容。

| 角色 | 工作单 |
|---|---|
| P1 数据与集成 | [P1工作单](P1_数据与集成_给成员AI.md) |
| P2 图谱与查询 | [P2工作单](P2_图谱与查询_给成员AI.md) |
| P3 代码与演化 | [P3工作单](P3_代码与演化_给成员AI.md) |
| P4 模型与知识抽取 | [P4工作单](P4_模型与知识抽取_给成员AI.md) |
| P5 原型与汇报 | [P5工作单](P5_原型与汇报_给成员AI.md) |
| P6 模型参考与实验 | [P6工作单](P6_模型参考与实验_给成员AI.md) |

P4使用macOS，其余Windows；P2使用现有DeepSeek可执行开发工具，其余五人Codex；全员已有DeepSeek API。AI负责实现、内容审核和实验流程，成员负责授权、预算、设备操作、理解与汇报、真实互评。不安排逐条人工标注评分。

## 检查规划资料

以下两个脚本只维护文档，不代表系统运行通过：

~~~text
python tools/sync_workorders.py
python tools/check_planning.py
~~~

Windows可使用py -3运行，macOS可使用python3。工具仅用Python标准库。六份工作单的公共段必须与统一契约一致，状态文件中的后续实现不得提前标完成。
