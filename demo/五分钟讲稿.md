# HistoryKG 五分钟讲稿

对应[五分钟汇报](五分钟汇报_课程采集版.pptx)，期中、期末均可用。按 4 分 45 秒讲述，留 15 秒切换。

**0:00–0:35｜为什么做。** 看当前代码，通常能知道它做什么，却很难知道为什么改。理由可能在 Issue 或评审里，改动在 PR 和提交里。我们输入一个公开 Python 仓库链接，把这些历史记录连成图，回答时给出可点回原文的出处。

**0:35–1:30｜系统怎么做。** 我们的采集模块直接读 GitHub，自动选取有限范围的 Issue 和 PR，逐页保存正文、评论和评审。每条材料留下原文、链接和采集缺口；如果请求中断，可以从已存的页面继续。然后程序补充提交和代码事实，用模型提取决定和理由，校验引文后建图。采集模块已经在 Flask 上在线验证；已有的冻结资料也能用当前程序重新建图和检索。

**1:30–2:30｜一个决定怎么连回原文。** Flask PR #6133 里，维护者说明调整测试是为了适应 Werkzeug 尚未发布。这里的决定是调整 Flask 测试，理由也来自原文。同一条讨论提到的 `client.query` 属于 Werkzeug。这就是为什么我们要保存证据并核对项目归属。

**2:30–4:05｜演示一个问题。** 打开已保存的 Flask 问答，选择「`FlaskClient.session_transaction` 承担什么职责？」点开证据 36，展示保存会话、更新 Cookie 的源码位置和原始链接。现场用[冻结回放](midterm/演示步骤.md)，让大家能看到答案如何回到出处。

**4:05–4:45｜实验说明了什么。** 旧版 Flask 实验在 30 个讨论上的抽取 F1 是 0.714。两组用同一批来源，B 组增加图扩展，事实覆盖从 0.600 到 0.740，但配对差的区间跨零。现行采集和索引已经做过工程验证；这里的质量分数对应 10 月 30 日的旧版实验。
